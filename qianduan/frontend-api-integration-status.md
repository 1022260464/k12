# K12 前端接口接入与待开发清单

本文记录 `user-app` 和 `admin-app` 的真实后端接入情况。前端统一通过 Gateway 的 `http://localhost:8080` 访问接口，不直接连接 IAM、Learning、Agent、Assessment 等微服务端口。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 页面已完成 | 页面、加载状态、空状态、错误状态和主要操作均已接入真实 API |
| API 已封装 | 前端 API 方法已存在，但完整业务页面或操作流程尚未实现 |
| 后端待开发 | OpenAPI 中没有对应接口，前端只保留明确的空状态或禁用入口 |

| --- | --- |
| 暂无 | 当前 OpenAPI 中已有的管理端资源操作均已提供 API 封装和页面入口 |

管理端不填充模拟数据。接口不可用时页面显示错误提示，写操作只能由后端成功响应后显示成功状态。

管理端编辑用户、课程、智能体和作业时，会先调用详情接口再打开表单，避免列表接口裁剪字段后出现编辑回显不完整。创建作业时从真实课程列表中选择课程，不要求管理员手填课程 ID。

当前用户模型没有班级、年级组织或教学组字段，因此“群体选择”先提供“全部启用学生”和“全选当前搜索结果”。后续若需要按班级、年级或课程成员布置作业，后端应增加学生分组/课程成员查询接口，前端再增加对应群组筛选，不应通过前端猜测分组。

## 鉴权与错误处理

- 两个应用都把 JWT 放在 `sessionStorage`，请求时统一附加 `Authorization: Bearer <accessToken>`。
- 后端返回 `401` 时会清除本地会话，用户需要重新登录。
- `403` 表示已经登录但缺少权限，不能通过前端隐藏按钮代替后端的 `@PreAuthorize` 校验。
- 页面必须显示加载、无数据和请求失败状态，不能用静态成功数据替代接口结果。

## 本地运行

```bash
cd qianduan
pnpm dev:user
pnpm dev:admin
```

- 用户端：`http://127.0.0.1:5173/`
- 管理端：`http://127.0.0.1:5174/`
- Gateway：`http://127.0.0.1:8080/`

联调前应启动 Gateway、IAM、Learning、Agent、Assessment 以及它们依赖的 MySQL、RabbitMQ 和 Python Worker。未启动某个服务时，对应页面会显示真实错误状态。
