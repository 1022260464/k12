# K12 AI 通识知识库补全计划

> 状态：待补资料清单与入库操作说明，非“内容已完成”证明。更新日期：2026-09-17。
> 本文只记录后续工作；编写本文未新增知识数据，也未连接或修改数据库。

## 1. 目标与边界

知识库要支持赛题要求的四个学段（小学低年级、小学高年级、初中、高中），让学生按学段或教材提问时，助教能检索到准确、适龄、可追溯的 AI 通识资料。补全知识库不等于堆积文档数量：每个核心主题至少要有学习目标、解释、例子、活动、常见误区、安全提醒和可核验来源，并通过教师审核和实际提问验证。

- 文本知识写入 PostgreSQL/pgvector 的 `k12_rag.knowledge_document` 与 `k12_rag.knowledge_chunk`；图片、音频、视频等大文件应放 MinIO，知识文档只保存资源说明和可访问的引用，不把二进制写入向量库。
- 课程发布、作业、评分、用户权限等仍由现有 Java 业务服务负责，不因为补知识库而迁移到 pgvector。
- RAG 是答疑和教学引导的知识来源，不是自动批改标准答案库。正式测验题目、答案、评分规则需要单独审核和接入考核业务。
- 本项目的主题目录参考 [教育部《中小学人工智能通识教育指南（2025年版）》](https://www.cse.edu.cn/index/detail.html?category=31&id=4240) 与 [UNESCO 学生 AI 能力框架](https://www.unesco.org/en/articles/ai-competency-framework-students?hub=66925)，但以下安排是项目实施清单，不宣称与任何官方教材完全等同。

## 2. 当前基线

仓库 `data/demo_knowledge.json` 当前有 14 条**演示资料**：小学低年级 2、小学高年级 3、初中 4、高中 5。内容已涵盖 AI 认识、模式识别、算法步骤、Scratch 条件、AI 安全、Python 变量、冒泡排序、训练/测试集、准确率、神经网络、梯度下降、大模型、RAG、校园项目。这些是文件现状；**本次没有查询 pgvector，不能据此认定数据库已有 14 条，也不能认定其达到正式教学质量。**

现有 `scripts/seed_demo_knowledge.py` 能按稳定 `document_id` 入库，重复导入会更新同 ID 的文档和片段。它没有预览模式，执行即写库；不要在未审核的新资料上直接运行。当前 `demo://` 来源地址只用于演示，不是真实可点击的教学出处。

## 3. 覆盖矩阵与优先级

建议先覆盖每个学段的基本概念、实践、伦理和评价，再扩充多模态材料。表中“已有”仅指仓库演示稿；“待补”是后续作者要完成的资料，不是当前功能已经实现。

| 学段 | 已有演示稿 | P0：先补齐的核心主题 | P1：再扩充的主题/实践 |
| --- | --- | --- | --- |
| 小学低年级 `lower_primary` | AI 是什么；寻找规律 | 人与 AI 的区别和边界；图像/声音如何成为信息；生活中的分类；隐私与求助 | 语音互动故事；图文辨别练习；用卡片模拟训练数据 |
| 小学高年级 `upper_primary` | 算法步骤；Scratch 条件；生成式 AI 安全 | 数据收集与标注；顺序/循环/条件的组合；智能设备的感知-判断-行动；AI 输出核查 | Scratch 小项目；简单推荐系统体验；图像识别偏差实验 |
| 初中 `middle_school` | Python 变量；冒泡排序；训练/测试集；准确率 | Python 条件/循环/函数；数据清洗与可视化；分类任务与特征；过拟合、数据泄漏和公平性；生成式 AI 的可靠性 | 不同排序算法比较；文本分类小项目；提示词设计与结果核查 |
| 高中 `high_school` | 神经网络；梯度下降；大模型；RAG；校园项目 | Python 数据处理；监督/非监督学习；精确率/召回率与混淆矩阵；模型局限与偏见；隐私、版权、学术诚信；智能体工具调用及安全边界 | 项目评估与复盘；检索评测；延迟/成本/效果权衡；部署与监控概念 |

四个学段的每个主题都要从三个角度检查：

1. **知识**：概念是否正确、适龄、有边界；不要把模型输出描述为事实保证。
2. **应用**：有一个学生能操作或观察的例子，具备前置知识和课堂反馈。
3. **责任**：涉及个人信息、训练数据、偏见、版权或错误答案时给出具体安全行为。

### P0 补充顺序

1. 先补“低年级安全与 AI 边界、高年级数据标注、初中 Python 控制结构、高中模型评价”，使四个学段都能走完基本教学流程。
2. 再补矩阵其余 P0 主题，并为每篇准备 3 个真实学生问法和 1 个越级问题。
3. 最后补 P1 资源与多模态链接。现有视频或绘本须确认授权；不以实时生成视频作为知识库完成前提。

完成标准不是固定篇数。建议先以“矩阵中全部 P0 主题均有审核通过的资料、每个学段能走通至少一条完整学习路径”作为第一版验收；篇数和章节可由课程负责人按教材再调整。

## 4. 单篇资料编写规范

一篇文档只讲一个主要知识点；标题用学生可能提问的术语，例如“图像分类为什么需要不同样本”，避免“第 4 讲”这类不含主题的标题。建议结构：

1. 适用学段、前置知识、学习目标和预计活动时长。
2. 正确且适龄的核心解释，区分事实、简化类比与尚有争议的说法。
3. 贴近该学段的例子、可操作活动或编程任务；写出预期观察结果。
4. 2～3 个常见误区及纠正，例如“AI 会思考”与“AI 能完成部分识别/生成任务”的区别。
5. 1～3 个形成性检查问题，附参考答案和理由；**不要把这部分直接当成已发布的自动评分试题**。
6. 安全、隐私和版权提醒，以及资料出处、作者、审核人、修订日期。

示例结构与现有 JSON 兼容。实际资料需替换示例文字，`document_id` 保持稳定且不超过 64 字符；`stage_code` 只使用现有四个值。`grade` 和 `textbook` 没有准确依据时填 `null`，不要为了“完整”虚构教材名称；精确过滤可能因错误元数据而漏召回。

```json
{
  "document_id": "k12-ai-upper-primary-data-labeling-v1",
  "title": "为什么图像识别需要给图片标注标签",
  "source_type": "teacher_authored",
  "source_uri": null,
  "stage_code": "upper_primary",
  "grade": null,
  "textbook": null,
  "chapter": "数据与人工智能",
  "content": "学习目标：……\n前置知识：……\n核心解释：……\n课堂活动：……\n常见误区：……\n形成性检查：……\n安全提醒：……",
  "metadata": {
    "tags": ["数据标注", "图像识别"],
    "difficulty": "基础",
    "contentStatus": "draft",
    "version": "1.0",
    "author": "待填写",
    "reviewer": "待审核",
    "reviewedAt": null
  }
}
```

`source_uri` 只填真实、可访问且有授权的资料地址；自编内容可先留空。外部资料用自己的话重新组织，记录出处和许可，不直接复制受版权保护的教材全文。入库前移除学生个人信息、密钥、内部地址和不可信材料中的提示词指令。

文件建议存放在 `data/knowledge/`，按学段拆分，例如 `lower_primary.json`。现有脚本一次只读取**一个非空 JSON 数组文件**；可逐个文件执行，或维护一个经过审查的合并文件。不要覆盖 `data/demo_knowledge.json` 以致演示数据丢失，也不要复用演示数据的 ID 来存正式稿，除非明确计划替换。

## 5. 作者补充与入库步骤

1. 选定矩阵的一项 P0 主题，确定作者、学段、学习目标、参考出处；在待办表中标记“草稿”。
2. 按上面的格式写资料，确保标题、正文、`metadata.tags` 含一致的关键术语；当前动态主题讲解会按提问短语匹配检索片段的标题或正文，术语不一致可能导致“查到资料但不触发讲解”。
3. 由教师或课程负责人审核事实、难度、活动安全性、版权与引用，标记“审核通过”；未经审核不得在正式教学环境发布。
4. 入库前检查 JSON 语法、ID 唯一性、字段长度、来源和个人信息；备份原文件，并确认 `.env` 指向**正确的目标库**。脚本目前没有 `--dry-run`，执行前务必确认环境。
5. 在 `ai-services/k12-agent-runtime/` 目录执行实际入库命令（需要 `K12_AGENT_RAG_ENABLED=true` 和 `K12_AGENT_RAG_DATABASE_URL`，且已执行 `sql/001_init_pgvector.sql`）：

   ```powershell
   uv run --env-file .env python scripts/seed_demo_knowledge.py --data-file data/knowledge/upper_primary.json
   ```

6. 检查脚本输出的文档数、片段数；再用检索接口或助教实测该学段、该主题的提问。重复执行同一 `document_id` 会替换该文档及其向量片段；修改正文时应复测引用结果。

现有单篇接口是 `POST /internal/v1/rag/documents/index`，HTTP JSON 使用 `documentId`、`sourceType`、`stageCode` 等驼峰字段；批量 JSON 文件用上面示例的下划线字段。二者不要混写。该内部接口需要遵守现有鉴权约定，不要暴露给学生端直接上传资料。

## 6. 验收与回归

| 检查项 | 第一版验收要求 | 记录方式 |
| --- | --- | --- |
| 主题覆盖 | 矩阵所有 P0 主题都有审核通过的资料；四个学段各有一条“入门→练习→反馈”路径 | 维护主题清单与审核状态 |
| 入库一致性 | 目标库内每个批准的 `document_id` 恰好一条文档且有片段；版本和来源与文件一致 | 查询 `k12_rag.knowledge_document`、`k12_rag.knowledge_chunk` |
| 适龄检索 | 同一问题按四个学段检索，返回内容不越级、不混用教材；对低龄提问不用高中公式直接作答 | 每主题至少 3 个真实问法和 1 个越级问题 |
| 引用真实性 | 助教仅在 `metadata.knowledgeGrounding.status=USED` 时展示引用，标题、章节、来源对应真实参与回答的资料 | API 响应和用户端回显截图 |
| 内容质量 | 教师复核准确性、活动可执行性、安全提醒；错误答案和无来源断言能被发现并修订 | 审核记录与修订记录 |
| 检索基线 | 先运行现有 `scripts/evaluate_rag_retrieval.py` 的 10 条样例；扩展样例集后记录命中率、错学段率，不把旧 10 条样例的结果当全面验收 | 版本化评测集和每次结果 |

可读数据库的人工核对 SQL（在**已确认目标库**中运行，仅查询）：

```sql
SELECT stage_code, COUNT(*) AS document_count
FROM k12_rag.knowledge_document
GROUP BY stage_code
ORDER BY stage_code;

SELECT d.document_id, d.title, d.stage_code, d.metadata->>'contentStatus' AS content_status,
       COUNT(c.chunk_id) AS chunk_count
FROM k12_rag.knowledge_document d
LEFT JOIN k12_rag.knowledge_chunk c ON c.document_id = d.document_id
GROUP BY d.document_id, d.title, d.stage_code, d.metadata->>'contentStatus'
ORDER BY d.stage_code, d.document_id;
```

联调时可运行 `uv run --env-file .env python scripts/smoke_teaching_assistant_rag.py`：`rag_retrieved=true` 表示检索到了资料，`rag_used=true` 表示资料送进模型生成；两者都不等于答案已通过教学审核。
