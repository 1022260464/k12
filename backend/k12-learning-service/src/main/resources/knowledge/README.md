# 知识点清单从哪来？

一句话：**系统里的知识点名单，主要来自旁边这个文件**  
`ai_literacy_catalog.json`

## 怎么理解三样东西

| 叫什么 | 白话 | 干什么 |
|--------|------|--------|
| 清单文件（JSON） | 写在仓库里的名单 | 规定有哪些知识点、学段、分类、谁连谁 |
| 系统里的清单 | 服务读进内存的那份 | 页面回退、同步时用这份 |
| 图谱（Neo4j） | 真正连成关系网的地方 | 章节绑定、先修推荐都靠它 |

改清单文件 ≠ 图马上变。正确顺序：

1. 改 `ai_literacy_catalog.json`（或配置指向的外部文件）
2. 管理端点 **「重新读清单」**（只更新系统读到的名单）
3. 再点 **「写进图谱」**（按名单去改图上的点）

仓库根目录 `sql/neo4j/ai_literacy_catalog.json` 只是备份对照，**服务不会读它**。要改就改本目录这份。

## 三个按钮分别干啥

| 按钮 | 白话 |
|------|------|
| 重新读清单 | 重新打开清单文件，记到系统里；图先不动 |
| 写进图谱 | 按清单把图上的点补齐/改掉（同编号会盖掉你在页面上改过的） |
| 一键初始化 | **不只是合并前两个**。还会先写入基础数据（约束、示例章节/资料），再执行「重新读清单 + 写进图谱」。新环境第一次用 |

在页面上单独新建/编辑某个点，会直接改图，**不会**自动写回清单文件。以后再「写进图谱」，清单里有的编号仍会盖掉页面上的改动。

## 想用外部文件（不用重新打包）

环境变量：

```text
K12_KNOWLEDGE_CATALOG_LOCATION=file:D:/data/k12/ai_literacy_catalog.json
```

改完外部文件 →「重新读清单」→「写进图谱」。

## 学段怎么写

用中文，可多选：`小学低年级`、`小学高年级`、`初中`、`高中`。  
字段用 `stages` 数组；`stage` 是拼起来给人看的。
