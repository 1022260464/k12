# PDF 解析与知识库质量升级规划

> 规划基线：2026-09-18。状态：待实施；本文不是已交付功能清单。
> 关联总体规划：[project-scope-and-roadmap.md](project-scope-and-roadmap.md) 的阶段 C。

## 1. 结论与范围

当前链路已经能让教师上传资料、人工审核和发布、手动触发入库，并能完成文本提取、向量检索、重排和回答引用。它是可用的原型，不是复杂教材 PDF 的高质量解析方案。PDF 结构化解析、按教学结构切分、质量验收和可解释的前端检索诊断，是正式扩充知识库前的**必做升级项**。

本计划依据用户提供的《pdf调研.md》《pdf输出对照.md》《tools调研.md》制定。调研报告包含 5 份受控样本和 2 份真实 PDF 的结果；其运行环境、样本与本项目不完全一致，仓库内也没有这些完整原始样本和输出，因此以下工具结论只能作为候选依据，不能写成项目已复现的性能或质量保证。

### 当前基线（已实现）

| 环节 | 当前实现 | 缺口 |
| --- | --- | --- |
| 资源治理 | Learning Service 管理 MinIO 文件、审核、发布及显式入库状态 | 审核前缺少解析预览、敏感信息和学段/年级一致性校验 |
| PDF 提取 | Python 使用 `pypdf` 的 `page.extract_text()`；入库限制 20 MB、100 页、20 万字符 | 无 OCR、版面/表格/公式识别，页码和坐标未随片段保存；复杂排版可能错序 |
| 切分 | 约 800 字符窗口、120 字符重叠，优先在换行或句末断开 | 不按标题、段落、表格和公式成块；字符数未与模型 token 上限协同 |
| 检索 | BGE-M3 密集向量 + pgvector 余弦召回，默认 20 候选，经 bge-reranker-v2-m3 重排取 5 条；支持学段等过滤和 Redis 缓存 | 缺少正式语料评测、低相关拒答门槛、结构化页码引用和关键词召回对照 |
| 前端 | 管理端可看入库状态/操作记录；学生端可看回答所用来源 | 管理端没有解析片段、检索命中与评测结果预览；学生端无页码/节标题/短摘录 |

`INDEX_SUCCESS` 只证明文档产生了片段并写入索引，不证明文本顺序、事实、年龄适配或回答质量正确。当前 10 条离线检索样例主要用于基线回归，不能替代真实教材验收。

## 2. 目标架构与工具选型

```text
教师上传 -> 文件和元数据预检 -> 解析预览与质量报告 -> 人工审核/发布
         -> 管理员显式入库 -> 结构化块 -> 版本化切分 -> Embedding/pgvector
         -> 过滤/召回/重排 -> 带页码和出处的引用 -> 前端展示与反馈
```

解析与索引都属于后台作业，不在学生实时提问链路执行。原件和解析产物放 MinIO；MySQL 记录资料状态、审核与解析任务/版本；pgvector 保存可检索片段。不要因为增加 PDF 工具而另建一套绕过 Java 权限和审核的公开入口。

| 场景 | 候选路线 | 决策条件与限制 |
| --- | --- | --- |
| 单栏、带文本层的普通教材 | PyMuPDF 快速路径，对照现有 `pypdf` | 先在项目样本上比较阅读顺序、漏字、耗时；达标后才替换 |
| 双栏、图表或复杂教材 | MinerU 结构化路径，保留 Markdown/JSON、图片和表格块 | 用户调研中短篇效果最好，但中文扫描件数字错误、超长报告失败；必须分段限流并复测 |
| 公式密集资料 | Marker 作为可选对照或专项解析器 | 调研中公式样本较强，但真实 PDF 曾异常退出；不设为默认依赖 |
| 扫描件 | OCR 专项队列与人工复核；先评估 MinerU，PaddleOCR 待独立环境验证 | 中文乱码或关键数字未达标时禁止自动入库，不能无提示退回低质量文本 |
| 文档元素识别 | Unstructured fast 作为可选结构标签基线 | 不把其 OCR 或复杂表格能力当成已验证能力 |
| Agent 按页阅读原件 | pdf-mcp 可选工具层 | 它不是高质量入库解析器；先完成稳定预解析与权限控制，再决定是否接入 |

《tools调研.md》中的 pgvector、MinIO 与当前存储边界一致；Neo4j 是另一个知识关系层规划，不承担 PDF 原文解析或向量检索。该文档里的其他通用 Agent、生成和沙箱工具不纳入本次 PDF 升级范围。引入工具前还须核对许可证、模型获取方式、资源占用、离线部署与版本锁定。

## 3. 解析与入库质量门槛

1. **文件预检**：限制大小/页数/耗时/内存，校验扩展名和文件签名、加密及损坏情况；记录 SHA-256、页数和来源许可。上传上限与入库上限不同，前端应在上传时明确告知“可保存但不可入库”的情况。
2. **教学元数据**：校验学段、年级、课程和教材的一致性。`LOW_PRIMARY` 搭配“高中”必须阻止发布或入库；禁止将简历、身份证明等含个人信息的文件当作公开教学资料。自动检测只能辅助，最终由审核人确认。
3. **解析标准输出**：统一输出 `documentId / parserVersion / sourceHash / pageNumber / sectionPath / blockType / text / table-or-formula / bbox? / confidence?`。图片及解析后的完整 Markdown/JSON 保存在 MinIO，片段只保存受控引用。页眉页脚、目录、重复水印须单独标记，不能无差别并入正文。
4. **质量报告**：统计逐页是否处理、空页/乱码比例、文本顺序、表格关键单元格、公式可读性、OCR 置信度与关键数字。解析部分失败时标记待复核，不允许以 `INDEXED` 掩盖漏页或错误数字。
5. **人工预览**：审核者在发布/入库前检查原件与解析片段对照，可驳回、修正元数据或选择重新解析。不得把自动解析成功当作内容真实、版权许可和适龄性审核通过。
6. **版本与回退**：记录解析器、切分规则、Embedding 模型和源文件哈希；重新入库使用现有稳定 `documentId` 原子替换，成功后使 Redis 缓存失效。失败时保留上一版可用索引或明确标记不可用，不暴露半成品。

解析作业要隔离不可信文件，限制并发与临时空间，避免大 PDF 或压缩炸弹耗尽 Python API/Worker 资源。长文档按页段处理并核对合并顺序；MinerU 或 OCR 超时不能悄悄降级成错误顺序的全文。

## 4. 结构化切分与检索升级

切分输入从“整篇纯文本”改成有序结构块。按 `文档 -> 章节 -> 标题 -> 段落/列表/表格/公式` 建立层级；片段保留节标题、页码范围、块类型、顺序和来源版本。普通段落按 token 预算切分并保留适量重叠；表格至少保留表头与对应数据行，公式与其解释不分离。不要把页眉、页脚、导航目录或相邻两栏的错序内容混成一个片段。

切分大小应以 **Embedding 最长输入、重排器 query+片段的 512 token 上限、回答上下文预算**共同确定，而不是把现有 800 字符直接换成任意固定 token 值。先做多档切分对照，再确定配置；记录 `chunkVersion` 和 token 数，给每个片段保留稳定 ID。建立片段去重、异常短片段和跨页边界检查。旧索引迁移采用小批量重建、抽样核对和可回退策略。

现有“密集向量召回 + 重排”继续作为基线，先补齐过滤、来源页码和低相关/无证据时的拒答或降级门槛。关键词或混合检索只在正式评测显示术语、公式、代码符号召回不足后引入；不要仅为“企业级”标签而替换 pgvector。阈值通过标注集校准，不能写死一个未经验证的分数。

## 5. 给前端返回什么测试与参考数据

**管理端：受控诊断数据。** 规划在现有“教学资料”详情中增加“解析预览、片段预览、检索试测、评测结果”视图，而不是把 Python 内部 RAG 接口或密钥直接给浏览器：

| 视图 | 建议响应字段 | 限制 |
| --- | --- | --- |
| 解析预览 | 解析器/版本、源文件哈希、页数、逐页状态、告警、少量原文/结构块对照 | 仅管理员或有权教师；大文本分页，未发布资料不出现在学生端 |
| 片段预览 | `chunkId`、节标题、页码范围、块类型、token 数、截断摘录、索引版本 | 不返回向量、内部 MinIO 密钥或整库数据 |
| 检索试测 | 问题、学段/年级/教材过滤、候选排序、召回分和重排分、片段短摘录、出处、耗时 | 标明“命中”不等于“答案正确”；仅允许访问授权资料 |
| 评测结果 | 评测集版本、Hit@K/MRR、空结果准确率、错学段数、逐题预期/实际与失败原因 | 标准答案和未审核内容只对管理/审核角色可见；留审计记录 |

**学生端：仅返回已发布、实际参与回答的参考资料。** 在现有 `knowledgeGrounding` 协议上逐步补 `title / chapter / pageRange / excerpt / resourceId` 和受控下载动作；同时显示“未检索到可靠资料/已降级”。不返回原始评测题、完整未审核片段、向量、内部 S3 地址或私有文件。Java Gateway/业务服务负责 JWT、RBAC、资料状态和归属校验；Python 内部接口只由服务端调用。前端摘录必须限长、转义，不渲染文档中的任意 HTML。

这同时满足“测试数据返回前端供参考”和未成年人/资料权限边界：**诊断测试数据给管理端，教学引用给学生端**。接口字段、OpenAPI、空状态、错误状态和分页方式在实现时同步确定。

## 6. 评测与验收

先把用户调研样本作为候选基准，补入 10-20 份有授权的真实 K12 AI 教材/课件 PDF，覆盖四学段、单栏、双栏、表格、公式、扫描件及长文档。每份选 3-5 页人工标注阅读顺序、标题、关键事实/数字、表格和页码；另建立至少 100 条分学段问答及无答案样例。个人简历等敏感文件不得作为共享测试语料。

| 验收维度 | 必须检查 |
| --- | --- |
| 解析 | 全部页面有处理结果或明确失败原因；关键数字、中文 OCR、表格与公式逐项人工对照；记录各解析器耗时与峰值内存 |
| 切分 | 标题和正文归属正确，表格/公式不被破坏，页码引用可回到原件；抽样查看片段和 token 统计 |
| 检索 | 版本化评测集计算 Hit@5、MRR、空结果准确率、跨学段误召回和引用定位；新方案与旧 800/120 基线同集对比 |
| 安全 | 无未发布、无权限或含个人信息资料泄漏；撤回后检索与下载均不可继续访问；测试内部接口不能被浏览器直接调用 |
| 运行 | 长文档、损坏文件、扫描件、重复入库、重试和回退；记录 p50/p95 解析时长、检索延迟、失败率与资源成本 |

最终数值阈值须在代表性样本上确立并经教师确认；不能拿调研报告的 5+2 份样本或现有 10 条演示检索题直接宣称“企业级达标”。硬性门槛先定为：不得静默漏页、不得错学段公开、不得泄露未审核或个人资料、不得将未核准 OCR 关键数字当作可靠依据。

## 7. 分阶段交付顺序

1. **P0：基线与治理**。收集授权样本、固定评测集与旧链路基线；补学段/年级和敏感内容拦截；定义结构化解析结果、任务状态及管理端预览接口契约。
2. **P0：解析与切分必做升级**。在独立 Worker 中接入经实测的普通/复杂 PDF 解析适配器，完成版面块、页码、表格/公式保护和 token 预算切分；解析预览需经过人工确认才可发布/入库。
3. **P0：可解释联调**。完成管理端片段/检索试测与评测结果展示、学生端页码摘录；进行重建索引、撤回、权限和完整 HTTP 链路回归。
4. **P1：专项增强**。仅在评测证实有收益时加入混合召回、公式专项 Marker、扫描件 OCR；长文档分段与限流验收后再扩大批量入库。
5. **P2：按需访问工具**。在权限、成本和引用一致性验证后，评估 pdf-mcp 给 Agent 做按页阅读；不将其作为入库升级的前置条件。

本轮仅记录规划，**未安装上述新解析器、未重建现有索引、未新增前端/后端接口，也未对调研样本重新跑分**。
