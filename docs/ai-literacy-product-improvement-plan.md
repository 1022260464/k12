# K12 人工智能通识教学助手后续改进方案

> 版本：1.0  
> 基线日期：2026-09-22  
> 对应赛题：JBGS-2026-02 多模态 K12 人工智能通识课教学助手对话智能体  
> 文档性质：产品、课程、交互与工程联合实施方案

本文用于纠正项目当前“工程底座较完整、赛题核心体验展示不足”的优先级偏差。后续开发应以
人工智能通识课程和学生学习效果为主线，安全、微服务、消息队列、存储、RAG 和代码沙箱作为
支撑能力，不再把基础设施数量作为主要成果。

## 1. 改进结论

### 1.1 项目最终定位

本项目是面向小学低年级、小学高年级、初中和高中的人工智能通识课程教学助手，不是覆盖
语文、数学、英语等全部学科的通用学习平台，也不是单纯的 Python 编程平台。

统一产品描述：

> 系统根据学生学段、教材、学习历史和答题表现，动态调整 AI 通识知识的深度、表达方式和
> 交互载体，通过对话、语音、绘本、动画、图形化编程、Python 实验与游戏化练习，形成
> “讲解、实践、评价、诊断、推荐”的持续学习闭环。

普通数学、语言和编程知识只能作为理解人工智能概念的辅助内容，不能替代 AI 通识课程主线。

### 1.2 当前能力与主要差距

| 领域 | 当前基线 | 改进结论 |
| --- | --- | --- |
| 四学段适配 | 后端档案、Agent 路由、部分话术和题目难度已区分 | 从“提示词适配”升级为课程、页面、交互和评价共同适配 |
| 对话问答 | 已有 LangGraph、模型、RAG、引用和会话基础 | 增加主动教学、短轮次任务和儿童安全表达 |
| 动画讲解 | 已有受控结构化步骤和排序动画 | 建设可复用 AI 概念动画模板库，不执行任意模型代码 |
| 编程实践 | 已有 Python 编辑器和云沙箱 | 小学增加 Blockly 图形化编程，初高中保留 Python |
| 游戏化练习 | 已有结构化小测和服务端判分 | 增加任务、关卡、即时反馈、星级和掌握度更新 |
| 绘本 | 尚未形成前台阅读闭环 | 先做审核后的绘本资源和阅读器，不开放实时无限生成 |
| 语音 | 尚未形成稳定能力 | 小学低年级加入朗读、语音输入和文字降级 |
| 前端 | 功能完整度高于年龄适配度 | 保留中高年级极简工作台，新增低龄模式和阶段化导航 |
| 工程底座 | Java 微服务、权限、存储、消息和 Python Runtime 较完整 | 暂停扩充非必要基础设施，优先完成可见教学价值 |
| Nacos | 依赖与可选配置已存在，默认关闭，主调用仍使用固定地址 | 比赛阶段冻结，部署优化阶段再做真正服务发现 |

### 1.3 优先级原则

1. 先完成一个高质量小学低年级闭环，再扩展主题数量。
2. 先让学段差异在页面和交互中可见，再扩充后端配置项。
3. 先实现稳定、可审核的多模态，再考虑高成本实时生成。
4. 每项能力必须落到学生操作和学习结果，不能只存在于架构图。
5. 比赛演示的稳定性高于技术数量，所有外部服务必须有降级说明。

## 3. 人工智能通识课程体系

### 3.1 一级课程领域

| 领域编码 | 课程领域 | 核心问题 |
| --- | --- | --- |
| AI-01 | 认识人工智能 | AI 是什么、能做什么、不能做什么 |
| AI-02 | 数据与表示 | AI 如何获得数据，数据、标签和特征是什么 |
| AI-03 | 算法与计算思维 | 顺序、条件、循环、分解和基本算法如何工作 |
| AI-04 | 机器学习 | 训练、预测、分类、误差和模型评估是什么 |
| AI-05 | 计算机视觉 | 机器如何识别图片、物体和场景 |
| AI-06 | 自然语言处理 | 机器如何处理文字、语音和意图 |
| AI-07 | 生成式人工智能 | 模型如何生成文本和图片，为什么会产生幻觉 |
| AI-08 | 智能体 | AI 如何使用目标、记忆、规划和工具完成任务 |
| AI-09 | AI 安全、伦理与社会 | 隐私、偏见、版权、核验、责任和合理使用 |
| AI-10 | AI 项目实践 | 使用图形化编程或 Python 完成适龄 AI 项目 |

### 3.2 四学段课程深度

| 课程领域 | 小学低年级 | 小学高年级 | 初中 | 高中 |
| --- | --- | --- | --- | --- |
| 认识 AI | 生活中的 AI 小助手 | 感知、判断、行动 | AI 系统构成与边界 | AI 技术体系与应用分析 |
| 数据 | 图片、声音和标签卡片 | 数据收集、分类和质量 | 数据集、训练集与测试集 | 特征、分布、偏差和数据治理 |
| 算法 | 按步骤完成任务 | 顺序、循环、条件积木 | 排序、搜索与流程图 | 复杂度、算法选择与实验 |
| 机器学习 | 教 AI 认动物 | 训练简单分类器 | 监督学习和模型评估 | 模型训练、指标、过拟合与调参 |
| 计算机视觉 | AI 为什么能看图片 | 像素、标签和分类 | 图像识别过程 | CNN 概念与图像项目 |
| 自然语言 | AI 如何听懂一句话 | 关键词、意图和回复 | 文本分类与语言模型 | Transformer、Embedding 和 RAG |
| 生成式 AI | AI 会讲故事但也会出错 | 提示词与事实核验 | 大模型、幻觉和版权 | Prompt、RAG、Agent 应用设计 |
| 智能体 | 会使用工具的 AI 伙伴 | 目标、步骤和工具 | 规划、记忆和反馈 | LangGraph 式流程与项目实践 |
| 安全伦理 | 不上传隐私、遇事求助 | 真假判断和数字足迹 | 偏见、版权和负责任使用 | 对齐、治理、攻击与防护基础 |
| 项目实践 | 卡片游戏和角色任务 | Blockly 小项目 | Python 小实验 | 完整 AI 项目与报告 |

### 3.3 单课标准结构

每个正式课程小节必须包含：

1. 学习目标：最多三个可观察目标。
2. 情境导入：一个适龄生活问题。
3. 核心讲解：由审核内容或 RAG 支撑。
4. 多模态活动：绘本、动画、拖拽、Blockly 或 Python 至少一种。
5. 形成性练习：2 至 5 个即时反馈任务。
6. 易错点说明：指出 AI 的能力边界和常见误解。
7. 学习结果：记录完成度、正确率、提示次数和知识点掌握度。
8. 下一步推荐：根据先修关系和表现推荐下一小节。

不得只创建课程标题和章节简介。章节下面必须有小节，小节必须有可学习正文或交互活动。

### 3.4 第一批正式演示课程

| 学段 | 课程 | 演示小节 | 核心交互 |
| --- | --- | --- | --- |
| 小学低年级 | AI 小侦探：机器怎样认识世界 | AI 为什么能认出小猫 | 语音导入、互动绘本、图片分类、星级反馈 |
| 小学高年级 | 我来训练一个小助手 | 数据和标签、条件判断 | Blockly、数据标注、分类小游戏 |
| 初中 | 从数据到模型 | 训练集、测试集和准确率 | 动画步骤、预测实验、即时小测 |
| 高中 | 构建可信 AI 应用 | Embedding、RAG 和智能体 | Python、知识检索、运行结果分析 |

比赛主演示选择小学低年级课程，另外三个学段用于展示系统可扩展性和难度梯度。

## 4. 四学段产品体验

### 4.1 学段选择与持久化

首次登录或档案未完成时，使用四张清晰卡片选择学段。选择结果写入学习档案，并影响：

- 首页推荐和课程排序；
- AI 助手语气、回答长度和主动引导策略；
- 默认多模态方式；
- 编程工具类型；
- 练习难度和反馈方式；
- 导航名称和信息密度。

用户可以在个人资料中修改学段，但修改后应提示推荐和课程难度将发生变化。

### 4.2 小学低年级模式

- 每屏只突出一个主要任务，减少导航项和技术术语。
- 使用大尺寸点击目标、插图、进度点和角色气泡。
- 回答采用短句，一次只解释一个概念。
- 默认提供朗读按钮和可选语音输入。
- AI 主动提出二选一或三选一问题，避免完全开放式输入。
- 练习采用拖拽、配对、排序和图片选择。
- 使用星星、徽章和任务完成动画，但不设计诱导性连续奖励。

### 4.3 小学高年级模式

- 保留故事任务，但增加知识卡片和简单术语。
- 编程入口默认进入 Blockly，而非直接进入 Python 编辑器。
- 支持预测、分类和条件逻辑实验。
- 反馈包含“哪里正确、哪里需要再试一次”。

### 4.4 初中模式

- 使用当前极简学习工作台的紧凑版本。
- 强调概念、动画、步骤、代码补全和实验结果。
- 引入准确率、数据偏差、模型错误等分析任务。

### 4.5 高中模式

- 保留高信息密度工作台、Monaco 编辑器和代码沙箱。
- 强调模型原理、实验设计、结果解释和项目式学习。
- 支持查看知识引用、运行日志和评估指标。

### 4.6 无障碍和儿童保护

- 所有关键操作支持键盘访问并具备可见焦点。
- 不仅依靠颜色表达正确与错误。
- 语音能力始终提供文字替代。
- 不公开学生真实姓名、班级和排行敏感信息。
- 低龄学生上传内容前给予隐私提醒。
- AI 不诱导学生提供电话号码、住址、学校等个人信息。
- 危险、成人或严重偏题内容进入受控拒答并建议联系教师或监护人。

## 5. 核心学习闭环

```text
登录或注册
  -> 完成学段与兴趣档案
  -> 系统推荐今日 AI 通识任务
  -> AI 教师主动导入情境
  -> 绘本/动画/讲解呈现知识
  -> 学生进行拖拽/Blockly/Python 实践
  -> 游戏化练习即时判定与解释
  -> 写入完成度、正确率、提示次数和掌握度
  -> 结合知识图谱检查先修缺口
  -> 推荐下一小节或补救任务
  -> 教师查看过程证据和学习报告
```

### 5.1 主动教学规则

AI 助手进入课程时不能只显示空输入框，应按以下顺序主动发起：

1. 读取当前课程、小节、学段和最近一次学习位置。
2. 用一句话说明今天的目标。
3. 给出两个可选入口，例如“先听故事”或“先玩分类游戏”。
4. 学习中每完成一个节点给予教学性反馈。
5. 学习结束后提出一道迁移问题，并推荐下一步。

### 5.2 个性化决策最小规则

| 条件 | 后续策略 |
| --- | --- |
| 正确率低于 60% | 降低表述复杂度，补充示例，安排同知识点低难度练习 |
| 正确率 60%–85% | 保持难度，追加一道迁移题 |
| 正确率高于 85% 且提示少 | 推荐关联或进阶知识点 |
| 连续两次超时或退出 | 缩短任务，优先图片/步骤交互 |
| 学生主动表达兴趣 | 在同学段范围内优先推荐相关项目 |

这些规则先以可解释的确定性策略实现，后续再由模型参与排序。模型不得直接修改正式成绩。

## 6. 多模态能力方案

### 6.1 对话与语音

前端增加语音输入、朗读、停止朗读和文字回退。比赛阶段可优先使用浏览器 Web Speech API，
不把语音模型部署作为前置条件。服务端仍保存文字转写后的受控内容，不默认保存原始儿童音频。

### 6.2 互动绘本

定义受控 Artifact，而不是让模型返回任意 HTML：

```json
{
  "kind": "PICTURE_BOOK",
  "schemaVersion": "1.0",
  "title": "AI 为什么能认出小猫",
  "pages": [
    {
      "pageNo": 1,
      "imageObjectKey": "picture-books/cat-ai/page-01.webp",
      "narration": "小智今天要学习分辨小猫和小狗。",
      "interaction": {"type": "CHOICE", "prompt": "你看到了什么？"}
    }
  ]
}
```

图片、配音和源文件存入 MinIO；MySQL 保存资源元数据、版本、审核状态和课程绑定。绘本必须经过
教师或管理员审核后发布。比赛阶段准备 2 至 3 本高质量固定绘本即可，不开放学生无限生成。

### 6.3 动画讲解

继续使用“模型生成受限 JSON、前端白名单组件渲染”的方案。第一批模板包括：

- 分类训练过程；
- 训练集与测试集分离；
- 神经网络信号传递；
- 关键词到意图识别；
- 检索、引用和回答的 RAG 流程；
- 智能体规划、工具调用和反馈循环。

每个模板必须支持播放、暂停、单步、重置和文字说明。非法字段应拒绝或降级为普通讲解。

### 6.4 图形化编程

小学高年级引入 Blockly，不复制完整 Scratch 产品。第一批积木：

- 开始、结束；
- 移动与等待；
- 顺序、循环和条件；
- 读取图片标签；
- 根据分类结果执行动作；
- 输出提示和得分。

工作区保存为 JSON；前端模拟角色和任务；需要执行 Python 时，将生成的受限代码提交现有沙箱。
禁止把未经校验的积木输出直接作为系统命令执行。

### 6.5 Python 编程

初高中继续使用现有 Monaco 和腾讯云沙箱主链路，本地执行仅作为开发保底。课程任务应提供：

- 预置代码框架；
- 目标和输入输出示例；
- 分级提示而不是直接给完整答案；
- 运行时间、错误信息和图表产物；
- 代码提交与知识点结果关联。

### 6.6 游戏化练习

游戏化不等于给选择题增加彩色背景。第一批支持：

- 图片分类；
- 拖拽配对；
- 步骤排序；
- 判断 AI 输出是否可信；
- Blockly 任务闯关；
- 简短选择与判断题。

每个任务返回即时反馈、解释、提示次数、得分和关联知识点。星星与徽章是反馈，不与公开学生
排名或付费功能绑定。

### 6.7 教学资源

视频、PPT、Word 和 PDF 以教师上传、管理员审核、智能体推荐为主。实时视频生成不进入比赛范围。
学生侧仅展示已发布、符合学段和课程上下文的资源，并通过短期签名地址访问对象存储。

## 7. 前端改造方案

### 7.0 双学生端总体策略

最终交付两套可互相切换的学生体验，但不建立两套互相复制的业务工程：

| 体验 | 适用学段 | 主要交互 | 视觉方向 |
| --- | --- | --- | --- |
| 小学端 | 小学低年级、小学高年级 | 角色引导、语音、绘本、图片任务、游戏化练习、Blockly | 明亮活泼、较大点击区、短文本、强反馈；低龄友好但避免过度婴幼儿化 |
| 初高中端 | 初中、高中 | 课程目录、AI教师、知识引用、Python/算法实验、项目任务、学习报告 | 白底蓝色、克制高效、接近 Kaggle 的学习工作台 |

两套体验共享认证、API Client、课程数据、作业、学习记录、Agent会话和权限。学段档案决定默认体验，
个人菜单允许切换预览；路由布局、导航和适龄组件独立，业务状态与后端接口不得复制两份。管理端仍为
单独一套工程，并提供两种学生体验的预览入口。

### 7.1 信息架构

学生端主导航调整为：

```text
首页 | AI 课程 | AI 教师 | 实验室 | 任务 | 学习成长
```

小学低年级可进一步简化为：

```text
今天学什么 | AI 小老师 | 我的奖励
```

“RAG、Agent Runtime、知识图谱、Artifact”等工程术语不得直接出现在儿童主界面。

### 7.2 首页

首页仅承担：继续学习、今日任务、适龄课程推荐、最近奖励和 AI 教师入口。避免堆放系统架构、
角色介绍和未开放能力。当前漫画风格主图可保留，但课程和行动按钮必须根据学段变化。

### 7.3 AI 课程页

- 一级领域筛选与课程路径；
- 课程、章、小节三级结构；
- 每个小节明确显示讲解、互动、练习和完成状态；
- 未完成先修内容时解释原因并提供补学入口；
- 不允许点击章节后只看到一句简介。

### 7.4 AI 教师

- 维持悬浮入口，但打开后使用柔和圆角、气泡、建议问题和明确关闭按钮；
- 低龄模式默认全屏或宽抽屉，避免狭窄聊天框；
- 显示真实引用、资源推荐和可继续的学习任务；
- 根据课程上下文主动开场；
- 不把内部运行状态或调试字段暴露给学生。

### 7.5 实验室

- 小学低年级：图片分类、卡片和角色任务；
- 小学高年级：Blockly；
- 初中：Blockly 与 Python 可切换；
- 高中：Python、图表和项目实验。

### 7.6 学习成长

将当前报告、排行榜和知识网络整合为学生可理解的成长页，展示：

- 已完成的 AI 领域；
- 知识点掌握趋势；
- 徽章和项目作品；
- 需要复习的内容；
- 下一步推荐及推荐原因。

排行榜默认展示匿名昵称或班级内范围，并允许学校关闭。

## 8. Agent 与 RAG 改造

### 8.1 Teaching Assistant 目标流程

```text
输入校验
  -> 读取学生档案、课程、小节和最近学习结果
  -> 识别教学意图与学段
  -> 判断是讲解、推荐、练习、绘本、动画还是编程任务
  -> Neo4j 查询先修和关联知识点
  -> pgvector 检索已审核正文并重排
  -> 生成适龄回答或受控 Artifact
  -> 安全校验和事实引用检查
  -> 保存运行与过程证据
  -> 更新形成性评价并给出下一步
```

### 8.2 工具路由

| 意图 | 工具或结果 |
| --- | --- |
| 解释概念 | RAG + 适龄回答 |
| 推荐课程/资源 | 课程目录、已发布资源、图谱关系，不只做关键词匹配 |
| 看故事/绘本 | 已审核 PICTURE_BOOK Artifact |
| 看动画 | 白名单动画模板 Artifact |
| 做练习 | GAME/QUIZ Artifact + Assessment 判分 |
| 图形化编程 | Blockly 任务配置 |
| 运行代码 | Agent Service + 隔离沙箱 |
| 查询学习建议 | 掌握度、最近结果和图谱先修关系 |

课程推荐意图应同时使用明确关键词、模型语义判断和目录约束。用户说“推荐监督学习课程”时，
即使知识点关键词不完全匹配，也应进入资源推荐流程，再由课程标签、Embedding 和图谱关系召回。

### 8.3 RAG 质量升级

沿用 `rag-document-quality-upgrade-plan.md`，重点完成：

- PDF 版面、标题层级、页码、表格和 OCR 识别；
- 按章节、语义和长度联合切分，而不是固定字符切分；
- 元数据包含学段、课程、章节、小节、知识点、页码、版本和审核状态；
- 检索采用向量召回、关键词召回、元数据过滤和 Reranker；
- 回答只显示实际使用的引用；
- 建立小学、初中和高中分层评测集；
- 不合格文档禁止进入正式知识库。

### 8.4 Neo4j 职责

Neo4j 用于存储知识点关系，不替代 pgvector 或 MySQL：

- `PREREQUISITE_OF`：先修关系；
- `RELATED_TO`：关联概念；
- `COVERS`：课程或小节覆盖知识点；
- `EXPLAINS`：资料解释知识点；
- `ASSESSES`：题目考查知识点；
- `NEXT_FOR`：经审核的候选学习路径。

Agent 使用图谱解释“为什么推荐这个内容”，正文和引用仍来自 pgvector，成绩仍写入 MySQL。

### 9.3 Nacos 决策

比赛功能闭环阶段维持当前状态：保留依赖和可选配置，默认关闭，固定地址保证本地演示稳定。

1. 核心学生演示闭环已经稳定；
2. Gateway 路由从固定 URI 改为 `lb://服务名`；
3. Feign 客户端不再用固定 `url` 绕过发现；
4. 配置中心具有命名空间、分组、权限和密钥治理方案；
5. Nacos 不可用时有明确启动或降级策略。

报告中的准确表述为“已预留 Nacos 配置和服务发现接入，本地演示使用显式地址”。在完成上述
验收前，不表述为“当前所有服务已通过 Nacos 动态发现”。

| --- | --- |

## 14. 成本与服务选型

- 文本生成使用现有百炼/千问配置，限制单轮上下文和输出长度。
- Embedding 和 Reranker 优先使用已选云服务；本地 BGE 仅用于开发或离线兜底。
- 绘本图片在比赛前预生成并审核，不按每次学生请求实时生成。
- 不提供实时视频生成，使用已审核视频或结构化动画。
- 语音优先浏览器能力；需要更高质量时再接单一云厂商语音服务。
- 腾讯云沙箱按真实编程任务调用，不因打开页面自动创建实例。
- Redis、MongoDB、Neo4j 和 RabbitMQ 均应允许按功能开关降级，主学习页面不得直接崩溃。

## 15. 指标与验收方法

### 15.1 产品指标

| 指标 | 建议目标 |
| --- | --- |
| 主演示闭环完成率 | 内部试用不低于 90% |
| 小学低年级单屏主要操作数量 | 不超过 3 个 |
| 低龄单次 AI 回复 | 通常不超过 3 个短段落 |
| 形成性练习即时反馈 | 提交后 1 秒内返回本地/服务端判定结果 |
| 普通 AI 对话首个可见反馈 | 2 秒内显示处理中状态 |
| 正式课程空小节 | 0 |
| 已发布资源无来源或无审核记录 | 0 |
| RAG 引用不可打开或指向撤回资源 | 0 |

### 15.2 技术验收

- JWT、角色和数据归属在接口端强制执行；
- 小学、初中和高中请求能够生成不同教学策略；
- Artifact 经过 schema 校验和白名单渲染；
- 沙箱超时、模型失败、RAG 空结果和对象存储失败均有受控降级；
- 学习事件重复提交具有幂等保护；
- 敏感配置不进入 Git、前端构建产物和普通日志；
- 发布、撤回、索引和引用状态保持一致；
- 主链路具备关联 `runId/sessionId/studentId/sectionId` 的审计能力。

### 15.3 教育验收

- 每节课目标、活动和练习相互一致；
- 同一知识点四学段材料不是简单缩短文字；
- 每道练习有答案、解析和知识点；
- AI 不把生成内容表述为绝对正确，关键事实可引用；
- 低龄内容经教师或教研人员审核；
- 推荐结果能够说明依据，而不是只输出一个课程名称。

## 16. 比赛演示脚本

建议主线控制在 10 至 12 分钟：

1. 选择小学低年级，首页自动切换为适龄任务。
2. AI 小老师主动邀请学生学习“AI 为什么能认出小猫”。
3. 学生听一页绘本朗读并回答图片问题。
4. 学生完成动物图片分类，系统解释标签和训练数据。
5. 播放“训练、预测、纠错”互动动画。
6. 学生完成两道游戏化练习，获得星星。
7. 学习成长页更新掌握度，并说明下一课推荐原因。
8. 快速切换到高中档案，展示同一主题变为 Python/模型评估任务。
9. 教师端展示课程活动编排、审核资源和学生过程证据。

工程架构只在最后用 1 至 2 分钟说明，重点解释为什么系统稳定、安全、可扩展，而不是逐个介绍
中间件。

## 17. 暂不实施范围

- 面向所有学科的通用智能答题；
- 学生实时生成长视频；
- 完整复制 Scratch 官方编辑器和社区；
- 未审核内容自动进入正式知识库；
- 大模型直接执行任意 HTML、JavaScript 或系统命令；
- 使用模型完全替代教师批改和教育结论；
- 在主闭环完成前继续增加新的数据库或同类云服务；
- 仅为了架构展示而强制启用 Nacos。

## 18. 完成定义

项目达到比赛原型“完整”至少需要同时满足：

1. 人工智能通识课程是首页和课程中心的明确主线。
2. 四学段不仅提示词不同，课程、交互、练习和界面也有差异。
3. 小学低年级至少有一个绘本、语音、互动练习完整闭环。
4. 小学高年级至少有一个 Blockly AI 项目。
5. 初高中至少各有一个动画或 Python 实验课程。
6. 学生结果能够更新掌握度并改变下一步推荐。
7. 教师能够配置、审核、发布并查看学习证据。
8. RAG 只使用已审核资料，引用可以追溯。
9. 模型、沙箱、存储或消息服务故障时有可理解的降级结果。
10. 演示环境可以按文档复现，主流程连续回归通过。

在满足以上条件前，应使用“基础平台和首批教学闭环已完成”的表述，不使用“所有功能均已完成”。

## 19. 立即执行清单

当前先完成剩余业务闭环和演示稳定性，双学生端作为最后一个前端阶段实施：

1. 完成课程小节、活动、练习判分、掌握度和下一课推荐的真实闭环；
2. 完成小学低年级绘本、语音和图片分类主演示内容；
3. 补齐初高中代表课程与 Python 实验内容；
4. 完成知识库质量、部署和演示回归；
5. 最后按阶段 P6 拆分小学端与初高中端体验，并完成无损切换。

Blockly 图形化编程不再列为待开发项，后续只做内容扩充和缺陷修复。
