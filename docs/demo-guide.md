# K12 平台全流程演示文档

面向答辩、验收与对外演示。按「准备 → 管理端铺底 → 教师备课 → 学生学习闭环 → 对照验收」顺序讲解，约 **25–40 分钟**（可按听众裁剪）。

部署与环境变量见 [deployment-guide.md](./deployment-guide.md)。教师专项验收清单见 [backend/docs/teacher-acceptance-guide.md](../backend/docs/teacher-acceptance-guide.md)。

## 1. 开场（1–2 分钟）

**一句话：** K12 多智能体教学平台 = 课程学习 + 作业测评 + AI 助教 / 编程实验 + 知识图谱与掌握度闭环，学生端与管理端分离。

**架构示意（口述即可）：**

```text
学生端 / 管理端 → Gateway → IAM / Learning / Agent / Assessment
                                      ↓
                              Agent Runtime（大模型 / RAG / 沙箱）
```

**本场将走通：** 账号与权限 → 知识图谱 → 课程与资料 → 作业 → 学生学课与 AI → 编程实验 → 排行榜与报告 → 个人资料。

---

## 2. 管理员：账号、权限与平台底座（约 5 分钟）

**入口：** http://localhost:5174 → 管理员登录。

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 2.1 | 登录管理端 | 进入完整管理菜单（用户、角色、知识图谱、智能体、审计等） |
| 2.2 | **用户管理** → 新建教师、学生（若尚未准备） | 教师可进「教师工作台」可见菜单；学生只能进学生端 |
| 2.3 | （可选）**角色与权限** 扫一眼 | 说明权限挂在角色上，改权限后需重新登录 |
| 2.4 | 用学生账号试登管理端 | 被拒绝，突出「前后端双端鉴权」 |
| 2.5 | **知识图谱** →「一键初始化」（Neo4j 已开时） | 力导向图出现分类与知识点；可点节点看详情 |
| 2.6 | （可选）**智能体管理** | 确认 `teaching-assistant`、`python-code-coach` 等已启用 |

**切换账号演示：** 退出 → 教师登录 → 侧栏应**看不到**用户管理 / 安全审计 / 智能体等 adminOnly 入口，只保留工作台、课程、资料、作业等。

---

## 3. 教师：备课发布闭环（约 8–10 分钟）

**入口：** 管理端，教师账号。

### 3.1 课程资源

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 3.1.1 | **课程资源** → 新建课程（标题、学段、简介） | 草稿；列表仅本人课程 |
| 3.1.2 | 进入章节管理，至少建 **1 章**，写导语或小节正文 | 可现场写「什么是数据」短文 |
| 3.1.3 | （可选）为章节绑定知识点（知识点选择器） | 与图谱联动，供 AI / 先修建议使用 |
| 3.1.4 | **发布**课程 | 学生端课程中心可见 |
| 3.1.5 | （可选加速）**批量导入** `course-import.json` 模板 | 说明支持 JSON 批量建课 |

模板路径：`qianduan/admin-app/public/templates/course-import.json`。

若已跑正式演示 SQL，可直接打开「人工智能通识 · 正式演示课」展示四章结构，跳过手建。

### 3.2 教学资料（需 MinIO）

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 3.2.1 | **教学资料** → 上传 PDF/文档，关联已发布课程（可选章节） | 草稿入库 |
| 3.2.2 | 教师提交审核 | 状态待审；教师**无**终审发布按钮 |
| 3.2.3 | 切换**管理员**审核 → 发布 | 强调「教务审核」边界 |
| 3.2.4 | （可选）触发资料索引 / RAG | 为后续 AI 引用铺垫（需 Runtime RAG） |

### 3.3 作业布置（Assessment）

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 3.3.1 | **作业管理** → 新建作业，关联本人已发布课 | 草稿 |
| 3.3.2 | 添加**接收人**（搜索学生，勿展示邮箱敏感信息） | 定向布置 |
| 3.3.3 | 题目：手工或导入 `question-import.json` | 选择题 / 简答均可 |
| 3.3.4 | （可选）题目附件上传 | 需附件开关 + MinIO |
| 3.3.5 | **发布**作业 | 指定学生在学生端「作业练习」可见 |

## 4. 学生：学习与 AI 闭环（约 12–15 分钟）

**入口：** http://localhost:5173 → 学生登录（或现场注册）。

### 4.1 首页与选课

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 4.1.1 | 登录后看首页推荐 / 导航 | 学习首页、AI 学习台、课程中心、作业、编程实验、排行、报告 |
| 4.1.2 | **课程中心** → 打开教师刚发布的课 → 报名 | 选课成功 |
| 4.1.3 | 阅读章节，停留或点进度 | 进度写入；可强调「可续学」 |
| 4.1.4 | （有附件时）下载课程 / 章节教学附件 | 签名 URL 可打开 |

### 4.2 AI 学习台 / 悬浮助教

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 4.2.1 | 打开 **AI 学习台** 或悬浮助手 | 教学助教 `teaching-assistant` |
| 4.2.2 | 提问示例：「用生活例子解释什么是数据」或「冒泡排序」 | 讲解 +（若有）动画 / 结构化回复 |
| 4.2.3 | 跟随小测 / 练习（若界面出现） | 掌握度回写，服务后续推荐 |
| 4.2.4 | （有图谱时）展示「先修缺口 / 下一主题」类建议 | 点题：图谱不是装饰，是导航 |

**话术提示：** 前端不直连 Python；一律经 Gateway → Agent Service → Runtime，便于鉴权与审计。

### 4.3 作业提交

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 4.3.1 | **作业练习** → 打开已布置作业 | 可见题干与选项 |
| 4.3.2 | 作答并提交 | 提交成功 |
| 4.3.3 | 切回教师端「提交与批改」 | 看到该学生提交（可口头批改） |

### 4.4 编程实验（需 Runtime + 沙箱或教练配置）

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 4.4.1 | 进入 **编程实验 / Code Lab** | 关联 `python-code-coach`（需已执行对应 SQL） |
| 4.4.2 | 让教练出题或粘贴简单 Python（如打印、求和） | 得到指导或沙箱执行结果 |
| 4.4.3 | （可选）说明配额 / 异步队列 | 有 RabbitMQ + Worker 时可提一句 |

沙箱不可用时：仍可演示对话式辅导，注明「执行环境未开」。

### 4.5 排行榜与学习报告

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 4.5.1 | **学习排行** | 有积分/进度相关展示；开 Redis 时可提缓存 |
| 4.5.2 | **学习报告** | 学习概览、掌握情况（有数据时更饱满） |

### 4.6 个人中心

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 4.6.1 | 打开个人资料弹窗 | 学习画像等字段 |
| 4.6.2 | （MinIO 开）上传头像 | 成功刷新；失败时用户可读提示，不暴露底层存储细节 |
| 4.6.3 | **修改密码** 弹窗 | 当前密码错误 → 字段下提示；确认密码不一致 → 即时提示 |
| 4.6.4 | 改密成功后重新登录 | 闭环 |

管理端个人中心可快速对照同一套改密 / 头像能力（管理员账号）。

## 5. 管理端对照与收尾（约 3–5 分钟）

| 步骤 | 操作 | 期望 / 话术 |
| --- | --- | --- |
| 5.1 | 管理员 **知识图谱** | 力导向图 + 统计；与学生所学知识点呼应 |
| 5.2 | （可选）**安全审计** | 说明登录失败锁定、异常行为等能力边界 |
| 5.3 | 工作台 / Overview | 课程、用户规模等总览（有数据时） |
| 5.4 | 总结三端价值 | 学生：学与练；教师：备与批；管理员：人、图、审 |

**结束语建议：** 平台已打通「教—学—练—评—图谱导航」主路径；RAG / 沙箱 / Redis 等为增强项，可按学校机房条件开关。

## 6. 精简版脚本（10 分钟闪电演示）

若时间极紧，只做下列 8 步：

1. 管理端管理员登录 → 知识图谱一眼  
2. 教师登录 → 已发布课或快速建一章并发布  
3. 教师发布一道简单作业给演示学生  
4. 学生端登录 → 报名读一节课  
5. AI 学习台问一句通识问题  
6. 提交作业  
7. 排行榜或学习报告扫一眼  
8. 改密字段校验或头像（二选一）

## 7. 演示数据与账号准备细则

### 7.1 用 API 创建用户（管理员 Token）

```http
POST http://127.0.0.1:8080/api/v1/iam/auth/login
Content-Type: application/json

{ "username": "<管理员>", "password": "<密码>" }
```

```http
POST http://127.0.0.1:8080/api/v1/iam/users
Authorization: Bearer <accessToken>
Content-Type: application/json

{
  "username": "k12_teacher_demo",
  "password": "K12Teach@2026",
  "displayName": "演示教师",
  "roleCodes": ["ROLE_TEACHER"]
}
```

学生同理，`roleCodes`: `["ROLE_STUDENT"]`，或学生端直接注册。

### 7.2 正式演示 SQL

1. 确认教师、学生用户已存在。  
2. 编辑 `k12_formal_demo_ai_literacy.sql` 顶部用户名。  
3. 在 `k12_business` 执行脚本。  
4. Neo4j：约束 + `002` + `003`，或管理端一键初始化后再绑章节知识点。  
5. 重启 Learning（若需）并重新登录相关账号。

### 7.3 演示当日口头 FAQ

| 问题 | 简答 |
| --- | --- |
| 家长角色？ | 当前实现以学生 / 教师 / 管理员为主 |
| 必须上云模型？ | 本地联调需配置百炼等 API Key；未配则 AI 段跳过 |
| 必须 MinIO？ | 无对象存储则跳过附件与头像，课与作业文本流仍可演示 |
| 数据在哪？ | 账号在 `k12_auth`；课/作业/Agent 记录在 `k12_business`；图谱在 Neo4j；向量在 pgvector（若开启） |
