# 毕业论文演示：本地最小严格版本改造方案

> 文档状态：目标方案，尚未实施  
> 适用场景：本科毕业论文、项目答辩、16GB Windows 本地演示  
> 版本日期：2026-10-28  
> 方案原则：不新增教学功能；只替换基础设施、降低本地内存占用，并保持现有核心教学闭环  
>
> 冲突处理：涉及毕业论文本地演示基础设施时，以本文件为当前执行基线

## 1. 目标与边界

本方案用于将当前平台改造为一套可在 16GB Windows 电脑上稳定运行的“本地最小严格版本”。本地 Docker 与 IDEA 可以同时打开，但不要求全栈在开发、构建和压测同时进行时始终保持低延迟。

### 1.1 目标

- 取消 PostgreSQL、MongoDB、MinIO 三个本地容器。
- 向量检索改用阿里云 DashVector。
- 对象文件改用阿里云 OSS Bucket。
- Agent 执行轨迹改为本地 JSONL 文件，或作为后续扩展接入阿里云日志服务。
- MySQL 用一个数据库实例承载 `k12_auth`、`k12_business`、`k12_rag` 三个独立 Schema。
- Redis、RabbitMQ 和本地图数据库继续保留。
- Nacos、Piston 保持关闭。
- 完整保留课程学习、RAG 问答、资源引用、练习判分、知识图谱、推荐和教师过程证据主链路。

### 1.2 非目标

- 本阶段不重写前端页面。
- 本阶段不新增教学主题，不调整课程产品范围。
- 本阶段不引入 Nacos。
- 本阶段不恢复 Piston。
- 本阶段不把多个 Java 服务合并为单体。
- 本阶段不将图数据库迁移到云端。
- 本阶段不允许为了降低内存而删除核心学习记录或引用证据。

### 1.3 “严格版本”的含义

“严格”指以下约束必须同时成立：

1. 演示启动时不依赖 PostgreSQL、MongoDB 和 MinIO。
2. 不保留“环境变量已切换，但 Compose 仍启动旧容器”的伪迁移状态。
3. 资源正文、向量索引和对象文件必须能够重新建立关联。
4. 检索失败时必须明确降级，不得静默返回无依据答案。
5. 资源撤回后不得继续参与检索。
6. 所有云服务凭据只从环境变量或服务器密钥文件读取，不写入数据库、日志或代码。
7. 迁移完成前不删除旧数据；完成回归后再停止旧容器。

## 3. 数据边界与组件职责

| 组件 | 权威数据 | 不负责的内容 |
| --- | --- | --- |
| MySQL `k12_auth` | 用户、角色、权限、会话安全数据 | 不存课程正文和向量 |
| MySQL `k12_business` | 课程、章节、作业、学习记录、知识点掌握度 | 不存完整向量 |
| MySQL `k12_rag` | 知识文档、片段正文、版本、审核和索引状态 | 不存高维向量 |
| DashVector | 向量、`chunkId`、过滤字段 | 不作为正文和审核状态的唯一来源 |
| 阿里云 OSS | 原始文件与生成产物 | 不保存业务权限和检索状态 |
| Redis | 缓存、排行榜、短期会话数据 | 不作为长期权威数据 |
| RabbitMQ | 索引、重排、异步任务消息 | 不作为任务结果数据库 |
| 本地图数据库 | 知识点、先修关系、课程覆盖和路径关系 | 不保存 PDF 原文和向量 |
| JSONL 轨迹 | Agent 执行过程证据 | 不作为业务状态机 |

### 3.1 MySQL Schema 原则

使用一个 MySQL 实例，但保持三个独立 Schema：

```text
k12_auth       安全与身份
k12_business   教学业务
k12_rag        RAG 文档与索引状态
```

不把 `sys_user`、课程表和知识片段表合并到同一 Schema。独立 Schema 可保留模块边界、迁移顺序、账号权限和备份粒度。

## 4. MySQL RAG 数据设计

### 4.1 设计原则

- MySQL 是知识片段正文、审核状态和版本信息的权威来源。
- DashVector 只保存可重建的向量索引。
- 向量写入失败不能回滚掉已经审核通过的正文。
- 检索只能使用 `INDEXED` 状态的数据。
- 资源撤回后，即使 DashVector 删除暂时失败，也不能继续返回该片段。

### 4.2 建议表结构

#### `k12_rag.knowledge_document`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `document_id` | VARCHAR(80) PK | 稳定文档编号 |
| `source_type` | VARCHAR(32) | `PDF`、`DOCX`、`COURSE`、`PICTURE_BOOK` 等 |
| `source_id` | VARCHAR(80) | 对应业务资源编号 |
| `title` | VARCHAR(500) | 文档标题 |
| `source_uri` | VARCHAR(1000) | 受控来源标识，不存临时签名 URL |
| `object_key` | VARCHAR(1000) | OSS 对象键 |
| `stage_code` | VARCHAR(32) | 学段 |
| `grade` | VARCHAR(32) | 年级 |
| `textbook` | VARCHAR(255) | 教材 |
| `chapter` | VARCHAR(255) | 章节 |
| `metadata_json` | JSON | 页码、审核、知识点等扩展元数据 |
| `version` | INT UNSIGNED | 文档索引版本 |
| `checksum` | CHAR(64) | 源文件或正文校验值 |
| `index_status` | VARCHAR(20) | `PENDING`、`INDEXING`、`INDEXED`、`FAILED`、`DELETED` |
| `last_error` | VARCHAR(1000) | 最近一次索引错误摘要 |
| `created_time` | DATETIME | 创建时间 |
| `updated_time` | DATETIME | 更新时间 |

#### `k12_rag.knowledge_chunk`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `chunk_id` | VARCHAR(160) PK | 片段版本编号，同时作为 DashVector 主键 |
| `document_id` | VARCHAR(80) FK | 所属文档 |
| `version` | INT UNSIGNED | 所属文档索引版本 |
| `chunk_index` | INT UNSIGNED | 文档内顺序 |
| `title` | VARCHAR(500) | 片段标题 |
| `content` | LONGTEXT | 片段正文 |
| `embedding_model` | VARCHAR(128) | 生成向量的模型 |
| `knowledge_code` | VARCHAR(128) | 绑定知识点 |
| `stage_code` | VARCHAR(32) | 学段 |
| `grade` | VARCHAR(32) | 年级 |
| `textbook` | VARCHAR(255) | 教材 |
| `chapter` | VARCHAR(255) | 章节 |
| `metadata_json` | JSON | 页码、段落和引用信息 |
| `vector_id` | VARCHAR(160) | DashVector 主键，默认等于 `chunk_id`，必须包含文档版本 |
| `index_status` | VARCHAR(20) | 片段向量状态 |
| `created_time` | DATETIME | 创建时间 |
| `updated_time` | DATETIME | 更新时间 |

`chunk_id` 和 `vector_id` 使用可重建的版本化格式：

```text
documentId::version::chunkIndex
```

必须在 `chunkIndex` 部分保留稳定补零顺序，例如 `000001`，避免同版本片段编号冲突。

必须建立：

- `(document_id, version, chunk_index)` 唯一索引。
- `(stage_code, grade, textbook)` 组合索引。
- `knowledge_code` 索引。
- `index_status` 索引。
- `content` 中文全文索引，使用 MySQL ngram 解析器。

#### `k12_rag.knowledge_index_task`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | VARCHAR(64) PK | 索引任务编号 |
| `document_id` | VARCHAR(80) | 文档编号 |
| `version` | INT UNSIGNED | 待处理版本 |
| `task_type` | VARCHAR(24) | `INDEX`、`DELETE`、`REINDEX` |
| `status` | VARCHAR(20) | `PENDING`、`RUNNING`、`SUCCESS`、`FAILED` |
| `attempt_count` | INT UNSIGNED | 重试次数 |
| `last_error` | VARCHAR(1000) | 错误摘要 |
| `created_time` | DATETIME | 创建时间 |
| `updated_time` | DATETIME | 更新时间 |

### 4.3 状态机

```text
PENDING -> INDEXING -> INDEXED -> SUPERSEDED
                    -> FAILED -> INDEXING
INDEXED -> DELETED
```

检索时必须同时满足：

```text
knowledge_document.index_status = INDEXED
knowledge_chunk.index_status = INDEXED
knowledge_chunk.version = knowledge_document.version
DashVector.version 与 knowledge_chunk.version 一致
```

## 5. DashVector 接入方案

### 5.1 目标接口

保留现有 `KnowledgeRepository` 接口，将当前固定的 pgvector 实现替换为：

```text
MySqlDashVectorKnowledgeRepository
```

实现接口：

```text
replace_document(document, chunks)
search(query)
delete_document(document_id)
close()
```

### 5.2 DashVector Collection 字段

| 字段 | 用途 |
| --- | --- |
| `id` | 等于版本化 `vectorId` |
| `embedding` | 1024 维或与实际模型一致 |
| `documentId` | 文档过滤 |
| `embeddingModel` | 防止混用不同模型的向量 |
| `stageCode` | 学段过滤 |
| `grade` | 年级过滤 |
| `textbook` | 教材过滤 |
| `knowledgeCode` | 知识点过滤 |
| `version` | 防止检索旧版本 |

正文、审核状态和权限不放进 DashVector 作为权威数据。

### 5.3 写入流程

```text
教师发布并确认入库
→ MySQL 事务保存文档和片段，状态 PENDING
→ MySQL 提交成功
→ RabbitMQ 发布索引任务
→ Worker 生成 Embedding
→ 写入 DashVector
→ MySQL 更新 INDEXED 或 FAILED
```

同一文档重新索引时创建新的 `version` 和新的向量主键。新版本成功前，旧版本保持
`INDEXED`；新版本切换成功后，旧版本改为 `SUPERSEDED` 并异步删除对应向量。检索只使用
文档当前版本已经完成索引的片段。

### 5.4 查询流程

```text
学生问题
→ 百炼生成查询向量
→ DashVector 按学段、年级、教材、知识点过滤并召回 chunkId
→ MySQL 按 chunkId 获取正文和元数据
→ MySQL 中文全文检索关键词候选
→ Python 使用 RRF 融合语义与关键词结果
→ 百炼 Reranker 精排
→ 返回答案和引用
```

### 5.5 降级策略

| 故障 | 降级行为 |
| --- | --- |
| DashVector 不可用 | 使用 MySQL 全文检索降级，标记 `retrievalMode=lexical_fallback` |
| Embedding 不可用 | 禁止生成无依据答案，返回明确不可用状态 |
| Reranker 不可用 | 使用 RRF 结果作为最终候选，并标记降级 |
| MySQL 不可用 | RAG 整体不可用，不从 DashVector 单独返回正文 |

## 6. 阿里云 OSS 接入方案

### 6.1 设计原则

- Bucket 保持私有。
- 数据库只保存稳定的 `object_key`。
- 不保存会过期的签名 URL。
- 浏览器访问通过后端生成短期签名 URL。
- 上传、读取和删除都必须经过权限校验。

### 6.2 统一对象存储接口

在 Java 和 Python 侧分别定义对象存储端口：

```text
putObject
getSignedUrl
deleteObject
objectExists
```

目标实现：

```text
AliyunOssObjectStorage
```

当前 MinIO 实现保留到迁移验收完成，之后从 Compose 和默认配置中移除。

### 6.3 OSS 配置

```env
K12_OBJECT_STORAGE_PROVIDER=aliyun_oss
K12_OSS_ENDPOINT=https://<region>.aliyuncs.com
K12_OSS_BUCKET=<private-bucket>
K12_OSS_ACCESS_KEY_ID=<secret>
K12_OSS_ACCESS_KEY_SECRET=<secret>
K12_OSS_PUBLIC_ENDPOINT=https://<public-bucket-domain>
K12_OSS_SIGNED_URL_TTL_SECONDS=900
```

必须验证：

- 上传 PDF、图片和 Agent 产物。
- 短期签名下载。
- 中文文件名和对象键转义。
- Bucket 私有访问。
- 删除对象。
- 过期 URL 不可继续访问。
- 头像、课程封面、绘本和附件的前端回显。

## 7. Agent 执行轨迹文件化

### 7.1 设计原则

MongoDB 当前保存的是辅助执行轨迹，不承担核心业务状态。迁移后使用 `AgentTraceRepository` 抽象，并新增：

```text
JsonlAgentTraceRepository
```

默认目录：

```text
data/agent-traces/YYYY-MM-DD/
```

文件示例：

```text
data/agent-traces/2026-10-28/<runId>.jsonl
```

### 7.2 记录字段

建议记录：

- `runId`
- `agentCode`
- `sessionIdHash`
- `stageCode`
- `event`
- `status`
- `model`
- `startedAt`
- `finishedAt`
- `durationMs`
- `retrievalMode`
- `citationCount`
- `tokenInput`
- `tokenOutput`
- `errorCode`

默认不保存完整学生问题、完整回答、姓名、手机号、头像地址和原始文件内容。需要调试时使用脱敏摘要。

### 7.3 运行要求

- 写入失败不能阻断 Agent 主流程。
- 按天创建目录，单文件设置大小上限。
- 默认保留 14 天，答辩归档版本可单独冻结。
- 超过保留期自动压缩或删除。
- 日志目录不提交 Git。

## 10. 分阶段实施

### P0：冻结基线

- 备份 MySQL、PostgreSQL、MongoDB 和 MinIO 数据。
- 记录当前核心 HTTP 回归结果。
- 记录 MySQL 表结构、RAG 表结构和知识点数量。
- 固定用于回归的教师账号、学生账号和演示课程。

完成标准：旧环境可恢复，当前主链路有基线结果。

### P1：建立抽象接口

- Python 增加对象存储端口和执行轨迹端口。
- Java 抽出统一对象存储端口。
- RAG 保留现有 `KnowledgeRepository` 接口。
- 配置中增加 Provider 枚举，不改变现有默认实现。

完成标准：现有 pgvector、MongoDB 和 MinIO 路径继续通过测试。

### P2：MySQL RAG Schema

- 新建 `k12_rag` 文档、片段和索引任务表。
- 增加每张表的权限和迁移脚本。
- 增加中文全文索引。

完成标准：空库初始化、重复执行和回滚脚本均通过。

### P3：DashVector 适配器

- 实现 DashVector 写入、过滤检索、删除和健康检查。
- 保留 MySQL 全文检索与 RRF。
- 增加超时、重试和降级。
- 增加真实 DashVector 小规模测试。

完成标准：语义、关键词、知识点过滤和撤回均通过。

### P4：数据迁移与重新索引

- 从 pgvector 导出文档和片段。
- 将正文和元数据写入 MySQL。

## 12. 安全与数据治理

- MySQL 不直接暴露公网。
- OSS Bucket 保持私有，使用短期签名 URL。
- DashVector API Key 只授予目标 Collection 所需权限。
- 不把学生姓名、手机号、完整对话和原始文件正文写入向量字段。
- Agent JSONL 默认脱敏，禁止保存访问密钥。
- 日志中的 DashVector、OSS 和模型服务错误必须隐藏密钥和签名参数。
- 数据迁移必须记录源文件校验值和重新索引批次。
- 删除资源采用“先禁止检索，后异步清理向量”，避免删除失败导致泄露。

## 13. 回滚方案

在严格回归完成前保留：

- PostgreSQL 数据快照。
- MongoDB 数据快照。
- MinIO 对象镜像。
- 旧 Compose 和旧 `.env` 的加密备份。
- 当前可用镜像标签。

回滚触发条件：

- DashVector 无法满足基本检索质量。
- OSS 签名地址或 CORS 无法稳定工作。
- MySQL 全文检索导致核心知识点命中明显下降。
- 连续两次主教学流程无法完成。
- Docker 在 16GB 主机持续 OOM。

回滚时只切换 Provider 和 Compose 定义，不恢复已删除的旧数据目录。
