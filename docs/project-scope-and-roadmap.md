# K12 AI 通识教学助手总体规划

> 文档基线：2026-09-15；最近进度同步：2026-09-23
> 对应赛题：JBGS-2026-02 多模态 K12 人工智能通识课教学助手对话智能体

本文统一项目定位、最终功能边界、系统主流程、当前进度和后续实施顺序。模块自己的 README
负责说明启动与代码细节；当局部文档与本文的产品范围冲突时，应先更新本文并同步局部文档。

教师评审后形成的课程、学段、多模态和前端体验改进，以
[K12 人工智能通识教学助手后续改进方案](./ai-literacy-product-improvement-plan.md) 为执行基线。
原有工程路线继续有效，但开发优先级调整为：先完成小学低年级可见教学闭环，再扩展图形化
编程、初高中课程、个性化和部署能力。

## 1. 项目定位

本项目不是覆盖语文、数学等所有学科的通用答题系统，而是面向小学低年级、小学高年级、
初中和高中的人工智能通识课程教学助手。

系统围绕一名学生的持续学习过程提供：

- 根据学段或教材调整知识深度、表达方式、交互形式和练习难度；
- 回答 Python、算法、机器学习、神经网络、计算机视觉、生成式 AI 和 AI 安全等问题；
- 主动引导章节学习，而不只是被动回答单轮问题；
- 通过动画、编程和游戏化练习形成多模态学习体验；
- 记录学习历史、掌握度和兴趣，形成“教学、练习、评价、推荐”的闭环。

面向学生只呈现一个统一的“AI 通识教学助手”。内部可以使用 LangGraph 节点或多个专业
执行器协作，但不能要求学生理解或手动选择底层 Agent。

## 2. 最终功能边界

赛题要求六类能力中至少实现三类。项目不追求把每一种生成能力都开放给用户，而是优先保证
教学效果、稳定性、可交互性和演示成功率。

| 赛题能力 | 最终方案 | 是否实时生成 | 比赛阶段优先级 |
| --- | --- | --- | --- |
| 对话问答 | 大模型 + AI 通识知识库 + 学段适配 | 是 | P0 |
| 多模态教学资源 | 教师上传或审核视频、Word、PPT，智能体按主题推荐 | 推荐实时，资源不实时生成 | P1 |
| 动画讲解 | 大模型生成受控步骤 JSON，React 动画组件渲染 | 是 | P0 |
| 绘本生成 | 预生成并审核少量低龄 AI 通识绘本，保存到对象存储 | 默认否 | P2 加分项 |
| 编程环境 | 大模型辅导 + 腾讯云 Agent Sandbox 受控运行 Python | 是 | P0 |
| 游戏化练习 | 大模型生成结构化题目，前端固定组件交互并自动评分 | 是 | P0 |

### 2.1 明确保留

- AI 通识课程对话与主动追问；
- 学段、年级或教材适配；
- 可播放、暂停、单步执行的交互动画；
- 选择题、判断题、排序题和闯关式练习；
- Python 代码编辑、运行、结果和图表产物展示；
- 教师审核后的课程视频、文档和课件推荐；
- 学习历史、掌握度、薄弱点和下一步内容推荐。

### 2.2 限制开放

- 绘本在比赛阶段以预生成资源为主，只允许教师或管理员触发生成和审核；
- 大文件和图片保存到 MinIO/COS，数据库只记录元数据和受控访问地址；
- AI 批改、诊断和学习建议保留人工复核入口，不直接替代教师结论。

### 2.3 明确不做

- 不向学生开放实时 AI 视频生成；
- 不让大模型返回并执行任意 HTML、JavaScript 或系统命令；
- 不在 FastAPI、Java 服务主进程中直接执行学生代码；
- 不把账号密码、JWT、模型密钥或云密钥写入数据库业务配置、Git 或前端；
- 不在比赛阶段同时接入多家云厂商的同类生成服务。

实时视频生成成本高、等待时间长、失败率和内容一致性风险较高。项目将视频定位为教师审核的
课程资源，将“动画讲解”实现为结构化数据驱动的前端交互动画。该方案仍然满足赛题的动画
讲解要求，而且比不可交互的视频更适合教学演示。

## 3. 目标用户流程

```text
学生登录
  -> 选择学段/年级/教材
  -> 进入 AI 通识课程或悬浮教学助手
  -> 提问，或由助手根据章节和学习记录主动引导
  -> Java 校验 JWT、权限、数据归属并创建运行记录
  -> Python Teaching Assistant 读取最小必要上下文
  -> LangGraph 判断意图和教学策略
       -> AI 通识知识库检索
       -> 分层解释和引用
       -> 生成动画步骤 / 游戏题目 / 编程任务
       -> 必要时调用代码沙箱
  -> 返回文本与标准化 Artifact
  -> 前端使用白名单组件安全渲染
  -> 学生完成追问、练习或代码任务
  -> Java 记录结果，更新掌握度和薄弱点
  -> 下一轮推荐内容和交互难度随之调整
```

必须形成的最小学习闭环是：

```text
学段适配 -> 知识讲解 -> 互动练习 -> 即时反馈 -> 学情更新 -> 下一步推荐
```

仅能聊天、不能记录结果和改变后续教学策略，不算完成个性化学习闭环。

目标架构另规划 Neo4j 知识关系层：存储 AI 通识知识点的先修/关联关系、章节覆盖、已审核资料和稳定题目映射，供答疑导航、课程覆盖检查、练习定位、薄弱点解释与下一主题推荐使用。Neo4j 只返回关系和稳定编码；正文继续由 pgvector 提供，题目、学生掌握度与成绩继续由 MySQL 保存。当前仓库尚未接入 Neo4j，不属于上图所示的已运行主链路；目标图须用虚线标注。

Python Runtime当前已经完成`teaching-assistant -> RAG -> 千问`主链路，并通过
`knowledgeGrounding 1.0`向用户端返回真实引用状态。用户端只显示实际参与回答的知识来源；
无匹配、未启用或服务异常时显示降级提示。检索质量由仓库内人工标注集持续计算Hit@K、MRR、
空结果准确率和耗时，后续正式课程资料接入时继续扩充该评测集。

2026-09-23 已完成比赛版知识库质量升级：PDF 页码、PPTX 幻灯片号、DOCX 段落号与标题上下文
进入切片元数据；切分优先遵循结构边界；密集向量与关键词候选以 RRF 融合后再重排；管理端提供
真实检索试测和来源定位。扫描件执行 OCR 质量门禁，低文本页会标记 `ocrRecommended`，纯扫描件
拒绝入库并提示先 OCR；云 OCR 作为后续可插拔解析器。详情见
[PDF 解析与知识库质量升级规划](rag-document-quality-upgrade-plan.md)。

| 模块 | 负责 | 不负责 |

| RabbitMQ | 长任务解耦、削峰、失败重试入口 | 永久业务状态 |
| MySQL | 用户权限和业务事务数据 | 大文件、向量检索 |
| PostgreSQL + pgvector | 知识片段和向量检索 | IAM 与业务事务主数据 |

### 5.1 2026-09-23 小学低年级「小猫课」闭环

应用代码已完成“选择小学低年级 → 进入 AI 为什么能认出小猫 → 阅读四页互动绘本 →
百炼云语音朗读/文字讲解 → 三关图片分类 → Assessment 服务端判分 → 更新图像分类掌握度 →
获得小猫图片侦探徽章 → 推荐下一节课”的专用流程：

- 小学学习台已经使用独立 `lower-primary-tutor` Agent code；它复用 LangGraph/RAG 基础设施，
  但服务端强制 `lower_primary` 策略，避免仅靠前端提示词伪装学段；
- 互动绘本已从课程内部步骤提升为小学 AI 学习台中的独立主题入口，初高中主题目录不展示；
- 小学端进一步新增独立「互动绘本」专题页和主导航入口；首页只负责导流，不再承载绘本正文；
- 小学 AI 学习台左栏已由通用算法/机器学习目录替换为个性化学习向导，优先显示下一步、
  薄弱知识点、推荐课程和绘本专题；初高中端继续使用专业主题目录；
- 成长页在小学端先展示推荐知识点和推荐课程，知识网络默认折叠为辅助功能；初高中端保留
  完整知识网络，推荐模块改为可折叠展示，避免左右栏内容高度不一致产生大片空白；
- 讲解正文改用安全 Markdown 渲染，朗读前移除 Markdown 标记；下一课使用稳定知识点编码，
  已补齐 `computer_vision.object_detection` 审定主题，避免再次落入“不支持主题”的通用提示；

- 学段通过 IAM 学习档案真实写入，未登录或非小学低年级均有明确入口保护；
- 语音由 Agent Service 鉴权代理 Python Runtime，浏览器不接触内部密钥；只有点击朗读才调用，
  百炼不可用时自动降级 Web Speech，屏幕文字始终保留；
- 图像分类题由审定的 Runtime Artifact 生成，带受控视觉字段；前端只提交选项，答案和分数由
  Assessment 根据当前用户拥有的 `runId` 服务端判定；
- 形成性练习继续写入 `assessment_ai_practice_attempt` 和知识点掌握度；徽章由已持久化的服务端
  判分记录推导，不能由前端伪造；下一课优先使用知识图谱，服务不可用时使用可解释确定性规则；
- 本轮用户端 28 项 Node 测试及生产构建、Runtime 教学 Agent/API 76 项定向测试、Agent Service
  8 项定向测试均通过；测试未触发百炼或其他付费云接口。Assessment 形成性练习回归沿用前序
  结果；2026-09-23 已在迁移后的真实数据库上完成三次连续 HTTP 验收，三轮均为 40/40、

### 阶段 G：双学生端体验与学段切换（最终前端目标）

目标：在同一学生应用和同一套业务接口之上，形成两套明显不同、可互相切换的学习体验。

当前状态（2026-09-22）：产品边界已确定，尚未开始整体页面拆分。Blockly 图形化编程能力已完成，
可直接作为小学端实验室的核心能力复用。

- **小学端体验**：面向小学低年级和高年级，视觉更活泼、图像比例更高、文字更短，突出角色引导、
  语音、绘本、游戏化练习、奖励反馈和 Blockly；“偏幼儿”只用于低龄交互表达，不使用会降低
  小学高年级认同感的婴幼儿化措辞；
- **初高中端体验**：保留白底蓝色、接近 Kaggle 的克制工作台，突出课程目录、AI 教师、知识引用、
  Python/算法实验、项目任务、学习报告和效率型导航；
- **切换机制**：登录后依据学习档案中的学段自动进入对应体验；个人菜单允许主动切换预览，切换后
  不重新登录、不丢失课程进度和会话；修改正式学段仍走档案更新与权限校验；
- **共享边界**：两套体验共享 Gateway、JWT、API Client、状态模型、课程/作业/Agent 数据、埋点和
  权限逻辑；只拆分路由布局、导航、视觉令牌和适龄交互组件，不复制后端及数据访问代码；
- **管理端边界**：教师/管理员端继续保持一套，不跟随学生端主题切换，但提供小学端和初高中端预览。

验收：同一账号可在两套学生体验间切换；同一课程进度、作业、对话和徽章保持一致；小学端主要
流程适合触控和低阅读量，初高中端保持信息密度与编程效率；刷新页面后仍保持最近选择的体验。

## 8. 演示最小闭环

建议使用“不同学段理解冒泡排序”作为主演示：

1. 学生选择小学高年级或高中；
2. 助手以对应难度解释冒泡排序；
3. 前端播放可单步控制的排序动画；
4. 助手生成一道排序闯关题并即时反馈；
5. 高中学生进入沙箱修改并运行 Python 代码；
6. 系统记录结果并推荐下一节内容；
7. 切换到另一个学段，展示表达和任务难度差异。

该演示同时覆盖年级适配、主动对话、动画、游戏、编程、即时反馈和学习路径，避免依赖昂贵且
不稳定的实时视频生成。

## 9. 完成定义

任何功能只有同时满足以下条件才标记为完成：

- 有真实业务代码，不以静态假数据代替后端结果；
- 有权限、数据归属和未成年人数据保护边界；
- 有正常、非法输入和外部依赖失败测试；
- 有数据库或消息结构的可重复升级方案；
- OpenAPI、前端状态和中文操作文档同步；
- 完成至少一次真实 HTTP 或消息链路验收；
- 模型功能有输出校验、超时、降级、成本记录和人工复核策略。
