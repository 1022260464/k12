# K12 AI 通识教学助手总体规划

> 文档基线：2026-09-14  
> 对应赛题：JBGS-2026-02 多模态 K12 人工智能通识课教学助手对话智能体

本文统一项目定位、最终功能边界、系统主流程、当前进度和后续实施顺序。模块自己的 README
负责说明启动与代码细节；当局部文档与本文的产品范围冲突时，应先更新本文并同步局部文档。

## 1. 项目定位

本项目不是覆盖语文、数学等所有学科的通用答题系统，而是面向小学低年级、小学高年级、
初中和高中的人工智能通识课程教学助手。

系统围绕一名学生的持续学习过程提供：

- 根据学段或教材调整知识深度、表达方式、交互形式和练习难度；
- 回答 Python、算法、机器学习、神经网络、计算机视觉、生成式 AI 和 AI 安全等问题；
- 主动引导章节学习，而不只是被动回答单轮问题；
- 通过动画、编程和游戏化练习形成多模态学习体验；
- 记录学习历史、掌握度和兴趣，形成“教学、练习、评价、推荐”的闭环。

面向学生只呈现一个统一的“AI 通识教学助手”。内部可以使用 LangGraph 节点或多个专业
执行器协作，但不能要求学生理解或手动选择底层 Agent。

## 2. 最终功能边界

赛题要求六类能力中至少实现三类。项目不追求把每一种生成能力都开放给用户，而是优先保证
教学效果、稳定性、可交互性和演示成功率。

| 赛题能力 | 最终方案 | 是否实时生成 | 比赛阶段优先级 |
| --- | --- | --- | --- |
| 对话问答 | 大模型 + AI 通识知识库 + 学段适配 | 是 | P0 |
| 多模态教学资源 | 教师上传或审核视频、Word、PPT，智能体按主题推荐 | 推荐实时，资源不实时生成 | P1 |
| 动画讲解 | 大模型生成受控步骤 JSON，React 动画组件渲染 | 是 | P0 |
| 绘本生成 | 预生成并审核少量低龄 AI 通识绘本，保存到对象存储 | 默认否 | P2 加分项 |
| 编程环境 | 大模型辅导 + 腾讯云 Agent Sandbox 受控运行 Python | 是 | P0 |
| 游戏化练习 | 大模型生成结构化题目，前端固定组件交互并自动评分 | 是 | P0 |

### 2.1 明确保留

- AI 通识课程对话与主动追问；
- 学段、年级或教材适配；
- 可播放、暂停、单步执行的交互动画；
- 选择题、判断题、排序题和闯关式练习；
- Python 代码编辑、运行、结果和图表产物展示；
- 教师审核后的课程视频、文档和课件推荐；
- 学习历史、掌握度、薄弱点和下一步内容推荐。

### 2.2 限制开放

- 绘本在比赛阶段以预生成资源为主，只允许教师或管理员触发生成和审核；
- 大文件和图片保存到 MinIO/COS，数据库只记录元数据和受控访问地址；
- AI 批改、诊断和学习建议保留人工复核入口，不直接替代教师结论。

### 2.3 明确不做

- 不向学生开放实时 AI 视频生成；
- 不让大模型返回并执行任意 HTML、JavaScript 或系统命令；
- 不在 FastAPI、Java 服务主进程中直接执行学生代码；
- 不把账号密码、JWT、模型密钥或云密钥写入数据库业务配置、Git 或前端；
- 不在比赛阶段同时接入多家云厂商的同类生成服务。

实时视频生成成本高、等待时间长、失败率和内容一致性风险较高。项目将视频定位为教师审核的
课程资源，将“动画讲解”实现为结构化数据驱动的前端交互动画。该方案仍然满足赛题的动画
讲解要求，而且比不可交互的视频更适合教学演示。

## 3. 目标用户流程

```text
学生登录
  -> 选择学段/年级/教材
  -> 进入 AI 通识课程或悬浮教学助手
  -> 提问，或由助手根据章节和学习记录主动引导
  -> Java 校验 JWT、权限、数据归属并创建运行记录
  -> Python Teaching Assistant 读取最小必要上下文
  -> LangGraph 判断意图和教学策略
       -> AI 通识知识库检索
       -> 分层解释和引用
       -> 生成动画步骤 / 游戏题目 / 编程任务
       -> 必要时调用代码沙箱
  -> 返回文本与标准化 Artifact
  -> 前端使用白名单组件安全渲染
  -> 学生完成追问、练习或代码任务
  -> Java 记录结果，更新掌握度和薄弱点
  -> 下一轮推荐内容和交互难度随之调整
```

必须形成的最小学习闭环是：

```text
学段适配 -> 知识讲解 -> 互动练习 -> 即时反馈 -> 学情更新 -> 下一步推荐
```

仅能聊天、不能记录结果和改变后续教学策略，不算完成个性化学习闭环。

### 4.1 模块职责

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| React | 页面交互、安全渲染 Artifact、练习操作 | 权限最终判定、直接连接数据库和模型 |
| Gateway | 统一入口、JWT 校验、路由 | 业务 CRUD、模型调用 |
| IAM | 用户、角色权限、账号安全、学段基础档案 | Agent 编排 |
| Learning | AI 通识课程、章节、教材和教学资源元数据 | 向量检索实现 |
| Agent Service | 运行记录、同步/异步调度、状态、产物归属 | 具体模型 SDK 和提示词 |
| Assessment | 题目、作答、评分、学习结果 | 执行不受控代码 |
| Python Runtime | LangGraph、模型、RAG、工具和产物生成 | 登录、RBAC、通用 CRUD |
| RabbitMQ | 长任务解耦、削峰、失败重试入口 | 永久业务状态 |
| MySQL | 用户权限和业务事务数据 | 大文件、向量检索 |
| PostgreSQL + pgvector | 知识片段和向量检索 | IAM 与业务事务主数据 |
| MinIO/COS | 图片、绘本、文档、代码运行文件 | 权限规则本身 |

## 5. 当前总进度

状态定义：

- `已完成`：代码和主要测试已存在；
- `部分完成`：已有骨架或局部链路，但尚未达到最终产品要求；
- `待验收`：已有代码配置，但没有完成目标环境的真实联调；
- `未开始`：当前没有可用实现。

| 领域 | 状态 | 当前结果 | 主要缺口 |
| --- | --- | --- | --- |
| 前端用户端 | 部分完成 | 登录、课程、作业、学情和 AI 悬浮入口已接 API | 对话会话、Artifact 动画/游戏/代码结果、个性化推荐 |
| 前端管理端 | 部分完成 | 用户、角色、课程、章节、Agent、作业、运行和审计页面 | 资源审核、知识库、统一统计、系统配置 |

| Learning | 已完成基础闭环 | 课程、章节、报名、进度和数据范围 | AI 通识课程数据、教材映射、资源上传审核 |
| Assessment | 已完成基础闭环 | 作业题目、提交、自动计分、教师批改和历史 | 游戏化练习会话、能力点掌握度更新 |

`teaching-assistant` 已能按学段讲解冒泡排序并输出动画步骤，但还没有接入真实模型与 RAG。

## 6. Nacos 当前状态与接入目标

Java 服务的 `application.yml` 已包含 Nacos Discovery、Config 和可选导入，依赖也已加入；但
`NACOS_DISCOVERY_ENABLED`、`NACOS_CONFIG_ENABLED` 默认都是 `false`。当前 Gateway 默认通过
固定的 `http://localhost:8081` 等地址转发。因此准确状态是：

```text
代码预接入完成，真实 Nacos 联调尚未完成。
```

下一阶段 Nacos 验收范围：

1. 为开发环境建立独立 namespace 和统一 group；
2. 发布各 Java 服务的非敏感配置 Data ID；
3. 启用五个 Java 服务的注册发现并检查健康实例；
4. Gateway 从固定 URL 切换为 `lb://服务名` 并完成全接口回归；
5. OpenFeign 在可用场景改为按服务名调用，保留本地直连降级方式；
6. 记录启动顺序、环境变量和故障排查步骤；
7. 验证 Nacos 不可用时的失败策略，避免配置误判为已生效。

数据库密码、JWT 密钥、RabbitMQ 密码、模型 API Key 不应以明文提交到 Nacos。Nacos 默认不是
密钥保险箱；比赛环境继续使用系统环境变量，后续如需集中管理，应使用 Nacos 加密插件或云
密钥管理服务。

Python Runtime 当前不必直接注册到 Nacos。它是 Agent Service 后面的内部执行器，由 Java
通过配置地址或 RabbitMQ 调用。先把 Java 微服务的 Nacos 链路验收完成，避免扩大联调范围。

## 7. 后续实施路线

### 阶段 A：配置与运行基线

目标：让团队成员能够用同一套配置启动系统。

- 完成 Nacos 注册发现和配置中心真实联调；
- 清理仓库中的敏感默认值，统一环境变量模板；
- 验证 Gateway、五个 Java 服务、MySQL、RabbitMQ 和 Python Worker 启动链路；
- 形成健康检查和最小回归脚本。

验收：Gateway 使用服务发现转发，关闭任一实例时能给出明确错误，仓库不包含真实密码。

### 阶段 B：AI 通识教学契约

目标：把主 Agent 从通用 Demo 改为赛题对应的 `teaching-assistant`。

- 定义学段、年级、教材、章节、兴趣和掌握度上下文；
- 定义主动引导、解释、追问、练习和反馈状态；
- 定义 `ANIMATION`、`GAME`、`CODE_RESULT` 等 Artifact；
- 使用确定性规则先完成一个 AI 通识主题闭环；
- 由产品样例转成自动化验收测试。

验收：同一主题对小学和高中输出明显不同的语言、深度、示例和练习。

### 阶段 C：真实模型与 RAG

目标：回答来自受控 AI 通识知识库，而不是只依赖模型记忆。

- 定义模型端口并接入单一云平台；
- 建立提示词版本、结构化输出校验、超时和降级；
- 使用 PostgreSQL + pgvector 完成分块、向量化、按学段过滤和引用；
- 建立小型离线评测集，检查正确性、引用和年龄适配。

验收：回答带可追溯来源，无资料时明确降级，不虚构教材内容。

### 阶段 D：三类核心多模态能力

目标：完成比赛必需且适合现场演示的多模态闭环。

- 动画：先做冒泡排序或神经网络传播的步骤 JSON 与 React 播放器；
- 游戏：先做选择题和排序题，记录作答、即时反馈和掌握度；
- 编程：接入 AGSX，运行预置 Python 代码并返回文本、图表或文件；
- 资源推荐：从教师审核资源中推荐视频、Word 和 PPT。

验收：四条链路均从真实对话触发，产生真实 Artifact 或学习记录，不使用伪造成功数据。

### 阶段 E：个性化闭环

目标：让系统根据历史表现改变下一次教学。

- 聚合对话、练习、作业、代码运行和兴趣数据；
- 更新知识点掌握度、薄弱点和推荐理由；
- 支持主动发起章节引导和复习提醒；
- 教师端可以查看依据并人工调整。

验收：同一学生连续完成两轮学习后，推荐内容和难度发生可解释变化。

### 阶段 F：加分能力与比赛交付

- 制作并审核一套低龄 AI 通识绘本；
- 完善监控、运行耗时、模型成本、失败率和审计；
- 完成部署脚本、演示数据、演示路径和故障降级；
- 编写项目报告：架构、模型策略、多模态路线、知识库、难题和解决方案。

## 8. 演示最小闭环

建议使用“不同学段理解冒泡排序”作为主演示：

1. 学生选择小学高年级或高中；
2. 助手以对应难度解释冒泡排序；
3. 前端播放可单步控制的排序动画；
4. 助手生成一道排序闯关题并即时反馈；
5. 高中学生进入沙箱修改并运行 Python 代码；
6. 系统记录结果并推荐下一节内容；
7. 切换到另一个学段，展示表达和任务难度差异。

该演示同时覆盖年级适配、主动对话、动画、游戏、编程、即时反馈和学习路径，避免依赖昂贵且
不稳定的实时视频生成。

## 9. 完成定义

任何功能只有同时满足以下条件才标记为完成：

- 有真实业务代码，不以静态假数据代替后端结果；
- 有权限、数据归属和未成年人数据保护边界；
- 有正常、非法输入和外部依赖失败测试；
- 有数据库或消息结构的可重复升级方案；
- OpenAPI、前端状态和中文操作文档同步；
- 完成至少一次真实 HTTP 或消息链路验收；
- 模型功能有输出校验、超时、降级、成本记录和人工复核策略。
